# Ziru Explainer｜子儒数字人科普视频

An agent skill for local presenter-led explainers: coherent stories, one voice, short AI presenter shots, and original code-driven motion graphics.

**技能名：`ziru-explainer` · 版本：1.1.0**

让使用者专注主题、稿件和成片效果，智能体负责事实核查、镜头安排、H3提示词、程序动画开发、配音与剪辑检查。适合知识讲解、商业案例和方法拆解。微电影、多人剧情和纯数字人长口播不沿用同一制作方案。

这是可复用的智能体技能与辅助工具。它不重新训练模型权重，不包含模型、私人人像或克隆声音；完整生成需要自行配置兼容的本地运行环境。

## 产品定位

Ziru Explainer把知识内容创作与本地媒体制作连接起来：先建立一个观众能持续听懂的问题链，再用人物表达、证据画面和程序动画共同解释。技能把内容决策、模型生成和后期合成记录为可检查的项目，便于复用成功素材、定位问题和进行局部修改。

典型用途包括商业案例拆解、知识科普、产品原理解说、专家观点与方法教学。使用者提供主题，确认口播核心内容与视觉方向；智能体维护分镜、英文模型提示词、代码与生产参数。调用者无需逐框编写模型提示词。

| 需要提供 | 将获得 |
|---|---|
| 主题或已有稿件、受众、用途、时长方向 | 有证据支撑的完整口播稿与叙事结构 |
| 可使用的案例、链接或素材线索 | 可核查的来源记录、案例细节与画面证据规划 |
| 已授权成年人物照片、声音方案 | 统一声线及必要的数字人短镜头 |
| 本地环境与工作目录 | 分镜、程序动画、时间轴、字幕、主片和分享版 |
| 对已有成片的中文修改意见 | 保留原版、仅更新受影响内容的修订版本 |

## 核心制作能力

**连续叙事与事实核查。** 从完整口播稿建立背景、行动、原因、结果和方法的承接关系；为数字、引语和因果判断记录来源。开头的悬念在正文中得到解释，结尾的方法从案例自然推导，不使用孤立金句代替论证。

**声音驱动的时间轴。** 固定一个配音身份与配置，完成旁白后以实际音频和词级对齐安排字幕、动画和切镜。声音、人物源偏移、画面时长分别记录，避免断字、空等、语速漂移和多条旁白叠加。

**两类镜头分别设计。** 数字人承担需要人物表达的观点与转折；程序动画承担数字对比、产品概念、流程和案例关系。H3生产单与动画开发单分别描述各自能执行的内容，避免用同一套模糊提示词统管两类工具。

**有依据的视觉连续性。** 从真实参考图建立身份、服装、画幅、光照、手部和既有道具约束；人物表演以克制动作和稳定构图为起点。对眼神、曝光、脸部比例和口型保留独立审核，参数选择不替代质量判断。

**可恢复的生产与修订。** 保存输入、配置、seed、请求图、任务ID、候选选择和检查结果。已有任务先核对再恢复；只改台词时，不重新生成所有已认可素材。失败候选与旧版保留，避免越改越难追溯。

## 制作流程

主题与证据 → 连续口播稿 → 内容确认 → 统一配音与对齐 → 系统拆镜 → 少量数字人＋程序动画 → 合成验收。

- 先把一篇稿讲顺，再按语义和实测声音拆镜，避免一句一镜导致割裂。
- H3提示词描述身份、表演、光线、手和道具连续性；动画开发单描述对象、排版、运动和信息揭示。两类单独维护。
- 用户主要审核内容与画面方向，模型提示词由智能体准备。
- 用统一旁白作为唯一主时钟；人物视频原声音轨在最终剪辑中静音。
- 局部改稿只重做受影响素材，保留成功片段和原版。

## 安装技能

将整个仓库放入客户端支持的技能目录，目录名保持`ziru-explainer`。支持Codex本地技能的环境可使用用户目录下的`.codex/skills/ziru-explainer`；其他智能体按自身的SKILL.md载入方式安装。

```text
ziru-explainer/
├── SKILL.md
├── agents/openai.yaml
├── references/
├── assets/
└── scripts/
```

可以直接把仓库地址交给智能体：

```text
请安装这个仓库中的 ziru-explainer skill，然后检查本地媒体制作环境。
暂时不要下载模型、调用付费服务或启动GPU生成。
```

安装技能只加载制作知识与工具；模型和运行环境按下一节分别配置。

## 硬件与软件

| 项目 | 本次验证配置 / 分享建议 |
|---|---|
| 系统与CPU | Windows11、i7-12700KF；其他现代桌面多核CPU需实际验证 |
| 显卡 | 实测RTX5080 16GB；建议以NVIDIA16GB显存为复刻起点 |
| 内存 | 实测64GB DDR4；建议64GB起评估 |
| 存储 | NVMe SSD，建议150–200GB以上空闲；五个H3相关模型文件已约40.28GiB |
| 数字人 | ComfyUI＋MiniMax H3＋T8音频节点＋Turbo节点/LoRA |
| 配音 | Ming-3.0-tts-0.5b |
| 检查/对齐 | Qwen3-ASR-0.6B＋Qwen3-ForcedAligner-0.6B |
| 动画/合成 | Python、Pillow、NumPy、OpenCV、FFmpeg/ffprobe、可合法使用的中文字体 |

这不是已证明的最低配置；其他显卡和跨系统整链尚未逐一实测。电源按具体显卡与整机厂商要求匹配。完整参数、版本快照、来源与安装顺序见[本地技术栈](references/local-stack.md)。

本次人物参数：原生1024×576、24fps、124帧约5.167秒、**8实际去噪采样步**、Turbo v4 step600 EMA LoRA1.0、Euler/simple、lock_source。最终1080p合成，默认关闭AI超分。8步不保证眼神或口型自动修好，1080p成片不等于1080p原生人物。

## 开始创作

```text
使用 $ziru-explainer。
主题：为什么很多产品参数很好，顾客却不愿意买？
受众：中小企业经营者；时长约3分钟。
先核查案例，写一篇连贯、有具体细节的完整口播稿，先不要生成媒体。
稿件确认后，使用我授权提供的成年人物照片和声音，
制作少量数字人镜头＋发布会风格程序动画。
人物先做8步＋Turbo LoRA短样片，关闭AI超分；项目放非系统盘。
H3表演提示词和程序动画开发单分别保存。
```

在线写稿和编程智能体仍可能消耗所选服务的Token。本地媒体推理不向在线视频生成API计Token，但仍有电力、时间和硬件成本。

## 辅助工具

将`assets/runtime.example.json`复制为自己项目的`runtime.json`，填本机位置。相对路径以配置文件目录为基准；模型名按本机ComfyUI下拉框/API枚举填写。

```bash
python scripts/doctor.py --config /path/to/runtime.json

# ComfyUI运行后只读取本机节点信息，不采样
python scripts/doctor.py --config /path/to/runtime.json --check-comfy

# 用已审核提示词绑定一个API请求，只写文件，不提交
python scripts/build_h3_request.py --config /path/to/runtime.json \
  --prompt /path/to/reviewed-prompt.txt \
  --image project/face.png --audio project/voice.wav \
  --out /path/to/request.json

# 对最终文件做完整解码、响度和黑场/冻结标记检查
python scripts/verify_delivery.py --config /path/to/runtime.json \
  --video /path/to/final.mp4 --report /path/to/new-report.json
```

H3模板是**ComfyUI API图**，不是可拖拽的前端画布工作流。提交前须核对节点schema、真实输入、授权和任务状态。成片检查器不执行ASR或主观观看，不自动意味着完整制作验收通过。

## 验证与局限

- 制作方法已在一条约3分13秒的成片中获得用户认可。
- 技能结构与辅助脚本行为经过本机验证；跨机器GPU生成尚未实测。
- 不含一键环境安装器、自动GPU排队器或可直接套任意主题的整片动画程序。动画由智能体按新主题编写。
- 不附赠私人素材、声音、聊天、模型、运行环境、字体或付费服务凭据。
- 原始实测机器曾出现显示故障；短任务、退出释放和间隔策略是保守调度，不是硬件健康保证。

## 成片验收依据

| 检查层 | 关注内容 | 证据与边界 |
|---|---|---|
| 内容 | 事实、数据、引语、叙事承接 | 来源台账、确认稿；奖项不替代销量或因果证明 |
| 声音 | 台词完整、数字/专名、段间响度、峰值 | 最终编码ASR、响度记录；ForcedAligner不替代独立识别 |
| 人物 | 身份、眼神、嘴型、手、道具、曝光、比例 | 样片/接缝/全片审核分别记覆盖范围，不能用抽帧冒充全片听审 |
| 程序画面 | 信息是否被解释、排版边界、运动与台词对齐 | CPU预览、关键帧和实际成片检查 |
| 文件 | 主片/分享版完整解码、音轨、尺寸、FPS、字幕 | FFmpeg/ffprobe报告、冻结/黑场逐项复核 |

常用交付目标为节目响度-16±0.5LUFS、真峰值不高于-1dBTP，按用途明确调整。本次用户认可版本实测为-16.16LUFS、-1.59dBTP，分段响度跨度0.86LU、相邻最大0.30LU；这些是单次工程结果，不是对所有输出的自动保证。

CPU辅助测试（Python3.10+，FFmpeg/ffprobe）：

```bash
python tests/test_helpers.py --work-dir /path/to/non-system-drive/test-work
```

测试生成约2秒的小型CPU视频，不加载AI模型、不使用GPU、不联网下载；每次保留独立测试记录。
