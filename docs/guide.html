安装与第一次使用

  1. 将包内 ziru-explainer 文件夹装入客户端支持的技能目录。支持Codex本地技能的环境通常放在用户的 .codex/skills/ 下；其他客户端按各自方式载入SKILL.md。原有项目与模型放非系统盘。
  2. 先装FFmpeg与CPU动画环境，再按上游说明配置ComfyUI、H3权重和节点。Ming/ASR各用兼容环境，避免一锅混装依赖。
  3. 将assets/runtime.example.json复制成项目runtime.json，填写本机工具、模型和ComfyUI输入目录。路径相对配置文件解析，不能原样照搬别人的F盘。
  4. 运行环境检查，随后用自己的图/声做一次短试听、CPU视觉预览与人物短样片。样片通过再开始完整制作。
python path/to/skill/scripts/doctor.py --config runtime.json

# ComfyUI启动后，仅检查本地节点，不采样
python path/to/skill/scripts/doctor.py --config runtime.json --check-comfy

把下面这段交给智能体即可开始：

使用 $ziru-explainer。
主题：为什么很多产品参数很好，顾客却不愿意买？
受众：中小企业经营者；时长约3分钟。
先核查案例，给我一篇故事连贯、有具体细节的完整口播稿，先不要生成媒体。
确认后，使用我提供的成年人物照片和声音，少量数字人镜头＋发布会风格程序动画。
人物先按8步＋Turbo LoRA短样片测试，关闭AI超分；工作目录放非系统盘。
H3表演提示词与程序动画开发单分别保存。

Python辅助脚本建议3.10以上；不同模型按自身上游支持的Python/PyTorch组合安装。未安装模型时doctor会报告缺项，不会偷偷下载。

最值得复用的经验

  1. 先把一篇文章讲顺，再按声音拆镜，避免一句一镜导致叙事割裂。
  2. 画面解释当前信息，用具体案例、数字和关系留住人，不让装饰运动抢内容。
  3. 同一声线、同一旁白、同一时间轴，避免人物与动画段落音量跳变。
  4. 小范围改稿只重做依赖素材，保留成功段落与原版，不每次全片返工。
  5. 按参考图保持人物和道具；异常短镜头可用更合适的照片/动画承接。
  6. 机器检查、抽帧、全片观看和用户满意分别记录，失败保留，不改门槛凑通过。

历史故障机使用一次一个短GPU任务、进程退出后至少60秒、与重CPU渲染错开；这是本机保守策略，不是通用安全承诺。新显示/PCIe故障即停止GPU，不能靠休息宣布硬件故障已解决。
